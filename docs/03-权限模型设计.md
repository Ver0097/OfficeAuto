# OA管理系统 - RBAC权限模型设计

## 1. 权限模型架构

采用标准RBAC模型：**用户 → 角色 → 权限（菜单）**

```
┌──────────┐     ┌──────────────┐     ┌──────────┐     ┌──────────┐
│  用户    │────▶│ 用户-角色    │────▶│  角色    │────▶│ 菜单权限 │
│ (User)   │     │ (UserRole)   │     │ (Role)   │     │ (Menu)   │
└──────────┘     └──────────────┘     └──────────┘     └──────────┘
```

---

## 2. 权限层级

### 2.1 三级权限结构

| 层级 | 类型 | 说明 | 示例 |
|------|------|------|------|
| 第一级 | 目录 | 菜单分组，无实际权限 | 系统管理 |
| 第二级 | 菜单 | 页面级权限，控制路由访问 | 用户管理页面 |
| 第三级 | 按钮 | 操作级权限，控制按钮功能 | 用户添加按钮 |

### 2.2 权限标识格式

```
模块:资源:操作

示例：
- system:user:add      用户添加
- system:user:edit     用户编辑
- system:user:delete   用户删除
- system:user:list     用户列表
- system:role:add      角色添加
- approval:leave:submit 请假提交
- approval:leave:approve 请假审批
```

## 3. 动态路由实现

### 3.1 后端：根据角色返回菜单

```java
/**
 * 获取用户菜单树
 * 流程：
 * 1. 根据用户ID查询角色列表
 * 2. 根据角色ID查询菜单列表
 * 3. 去重并构建树形结构
 * 4. 返回前端可访问的菜单
 */
@GetMapping("/user/menu")
public Result<List<MenuVO>> getUserMenu() {
    Long userId = SecurityUtils.getUserId();
    List<MenuVO> menus = menuService.getMenusByUserId(userId);
    return Result.success(menus);
}
```

### 3.2 前端：动态注册路由

```javascript
// router/dynamic.js

/**
 * 动态路由加载流程：
 * 1. 用户登录后调用 /user/menu 获取菜单
 * 2. 将菜单转换为路由配置
 * 3. 使用 router.addRoute() 动态注册
 * 4. 存储到 Vuex 中持久化
 */

function generateRoutes(menus) {
    return menus.map(menu => {
        const route = {
            path: menu.path,
            name: menu.name,
            component: () => import(`@/views/${menu.component}.vue`),
            meta: {
                title: menu.name,
                icon: menu.icon,
                perms: menu.perms  // 权限标识
            },
            children: menu.children ? generateRoutes(menu.children) : []
        };
        return route;
    });
}

// 动态添加路由
async function loadDynamicRoutes() {
    const { data } = await api.getUserMenu();
    const routes = generateRoutes(data);
    routes.forEach(route => router.addRoute(route));
    store.commit('SET_ROUTES', routes);
}
```

## 4. 权限控制方式

### 4.1 后端：注解式权限校验

```java
// 使用 Spring Security + 自定义注解

@RestController
@RequestMapping("/system/user")
public class UserController {

    @RequiresPerms("system:user:list")
    @GetMapping("/list")
    public Result<List<UserVO>> list() {
        // 需要 system:user:list 权限才能访问
    }

    @RequiresPerms("system:user:add")
    @PostMapping
    public Result<Void> add(@RequestBody UserDTO dto) {
        // 需要 system:user:add 权限才能访问
    }

    @RequiresPerms("system:user:edit")
    @PutMapping
    public Result<Void> edit(@RequestBody UserDTO dto) {
        // 需要 system:user:edit 权限才能访问
    }

    @RequiresPerms("system:user:delete")
    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable Long id) {
        // 需要 system:user:delete 权限才能访问
    }
}
```

### 4.2 前端：指令式权限控制

```javascript
// directives/permission.js

/**
 * 权限指令 v-perms
 * 使用方式：v-perms="['system:user:add']"
 * 无权限时移除元素
 */

app.directive('perms', {
    mounted(el, binding) {
        const perms = binding.value;
        const userPerms = store.state.user.permissions;

        const hasPermission = perms.some(p => userPerms.includes(p));
        if (!hasPermission) {
            el.parentNode?.removeChild(el);
        }
    }
});

// 使用示例
<el-button v-perms="['system:user:add']">添加用户</el-button>
<el-button v-perms="['system:user:edit']">编辑用户</el-button>
<el-button v-perms="['system:user:delete']">删除用户</el-button>
```

## 5. 权限校验流程

```
┌─────────────────────────────────────────────────────────────┐
│                     请求到达后端                              │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│              JWT Filter 解析 Token                           │
│              获取用户ID和角色信息                              │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│              权限拦截器检查接口权限                            │
│              @RequiresPerms 注解校验                          │
└─────────────────────────────────────────────────────────────┘
                          │
              ┌───────────┴───────────┐
              │                       │
              ▼                       ▼
     ┌────────────────┐      ┌────────────────┐
     │  有权限：继续   │      │  无权限：拒绝   │
     │  执行业务逻辑   │      │  返回403错误   │
     └────────────────┘      └────────────────┘
```

## 7. 权限缓存策略

```java
/**
 * 权限缓存设计：
 * 1. 用户权限缓存在 Redis
 * 2. Key: user:perms:{userId}
 * 3. Value: Set<String> 权限标识集合
 * 4. 角色变更时清除缓存
 */

@Service
public class PermissionService {

    @Cacheable(value = "user:perms", key = "#userId")
    public Set<String> getUserPermissions(Long userId) {
        // 查询用户角色
        List<Long> roleIds = userRoleMapper.selectRoleIdsByUserId(userId);
        // 查询角色菜单
        List<Long> menuIds = roleMenuMapper.selectMenuIdsByRoleIds(roleIds);
        // 查询菜单权限标识
        Set<String> perms = menuMapper.selectPermsByIds(menuIds);
        return perms;
    }

    @CacheEvict(value = "user:perms", key = "#userId")
    public void clearUserPermissionCache(Long userId) {
        // 角色变更时清除缓存
    }
}
```
